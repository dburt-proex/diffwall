## Decision

Publish one immutable `v0.2.0` tag and matching GitHub Release after the complete release-readiness matrix succeeds on `main`.

This authorization covers a pinned experimental release for controlled evaluation and pilots. It does not authorize enterprise-readiness, certification, universal-coverage, customer-adoption, or guaranteed-prevention claims.

## Governed exception

The candidate self-scan routed the original release-preparation pull request to `HALT` at 78/100 because it changed a protected workflow, `package.json`, and release infrastructure. The final publication increment also routes to `HALT` because it deliberately changes protected workflows and adds the dependency lockfile. These are the exact change classes this release gate is designed to escalate.

The owner accepts that route as a valid change-control signal and explicitly overrides it for this bounded release because:

- the protected changes are the intended release mechanism and dependency controls;
- independent CI and the full release-readiness matrix passed;
- the release is immutable and rollback uses a new superseding version rather than moving the tag;
- maturity and claim boundaries remain explicit.

This exception applies only to the `v0.2.0` publication increment. It does not weaken downstream DiffWall policy or create a standing override.

## Residual risks

- No completed external buyer pilot exists.
- The performance fixture is synthetic and does not prove universal repository performance.
- Long-lived audit storage remains caller-owned.
- Official GitHub Actions use maintained major-version tags rather than commit-SHA pins.
- DiffWall has not completed an independent penetration test or long-duration production operation.

## Reversal condition

Never move or silently replace `v0.2.0`. If a material defect is found, document it, mark the release as affected, and publish a new reviewed version.
